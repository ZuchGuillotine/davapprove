# Site envelope coordination viewer

November 7 automation direction: [Automated pre-check pipeline](AUTOMATED_PRECHECK_PIPELINE.md) defines the next architecture: machine-validated evidence, scoped revision reconciliation, automated geometry and exception-based human review. It supersedes blanket manual-acceptance design requirements below; existing runtime behavior remains unchanged until implemented.

Deployed to the beta environment November 7, 2026. Accuracy benchmarking will proceed with beta-user review.

The viewer renders vector geometry without remote tiles or WebGL. Discipline toggles, zoom, directional pan, fit, feature selection and source inspection operate in the browser without additional rendering infrastructure. Accepted features use solid outlines; proposed features use dashed outlines; geometric coordination overlaps use red overlays. These are application conventions, not a claim of compliance with a particular CAD drafting standard. Conflicts remain visible when disciplines are hidden.

Geometry review can add septic, ecology, civil, utilities, architecture or survey features as exclusions, proposed designs or references. Record the source URL, source design revision and sheet/page. Installed features must be supported by record drawings; installation and source decisions remain separate from geometry acceptance. Import buffer polygons explicitly from reviewed evidence; the application does not invent legal buffer distances.

## Extracted geometry interface

Assessment consumes facts whose `key` is `site_geometry`. Their object `value` contains `geometry` (Polygon/MultiPolygon), `crs: EPSG:4326`, `calibration: reviewer_confirmed`, `label`, `discipline`, and `role` (`design`, `exclusion`, `reference`). Preserve `design_revision`, `sheet`, `accuracy`, `work_stage`, `source_decision`, and `installation_status` when available. Fact provenance supplies `document_id` and `page`; project review supplies acceptance, corrected values and reviewer attribution. Missing source calibration produces an explicit gap and no plotted location. Rejected facts are omitted. Proposed geometry cannot subtract from the accepted envelope.

Overlap checks use the existing local feet projection and report intersecting design/exclusion pairs, source layer IDs, intersection geometry and area. Overlapping exclusions alone are not contradictions. These are coordination warnings, not agency determinations. Existing sketch/setback checks are retained.

## Remaining work

The parser now proposes `site_geometry` facts through the drawing observation and calibration path described below. Existing accepted text, including septic approval or installation statements, cannot locate a system. Use reviewed source geometry imports for unsupported drawing conventions or failed calibration. This change does not locate the user's actual septic installation or assert its buffers. Adjacent parcel acquisition, line/point utility features, automatic cross-sheet alignment, semantic contradictions (capacity, dates, alternate revisions), revision comparison/merge, and discipline-specific drawing-symbol ingestion remain pending. No automatic supersession of accepted geometry is implemented. A proposed design must be reviewed in project context.

Validation covers subtraction, proposal isolation, calibration gating, overlap detection and layer visibility/source inspection. No survey accuracy or agency compliance validation is claimed.


## Automatic drawing interpretation (deployed November 7 follow-up)

The vision extraction schema now includes closed feature outlines, explicit dimension endpoints/units/notations, physical feature identifiers, sheet/revision and explicit WGS84 controls. A versioned prompt invalidates prior extraction caches without replacing accepted facts. Text extraction separately captures printed engineering, architectural fractional-inch and ratio scales; paper scale alone cannot calibrate a resized scan. The existing model, budget reservations and page coverage mechanism are retained; no additional hosted viewer or rendering service is introduced.

A deterministic orientation-preserving similarity transform uses two controls and checks at least one independent noncollinear control. It preserves source observations and transform parameters. Pilot QA thresholds are a 1 ft control residual and 2% dimension/scale disagreement; these are application screening limits, not engineering tolerances. Mirroring, degeneracy, missing controls and inconsistent dimensions prevent geographic output. Dimension-only drawings receive a scaled sheet preview, not an invented parcel location. Model-generated outline precision is not validated by a good control fit alone.

Successful automatic fits appear as proposed overlays. Accepting an extracted fact alone does not make its geometry an envelope exclusion: the correction dialog separately asks the reviewer to confirm controls, dimensions and placement, and records `reviewer_confirmed` in the revision. Failed fits retain issues and sheet previews. All geometry retains document/page, hash and processing provenance via its fact record.

Reconciliation runs across project facts at assessment time, including newly parsed proposed observations. It matches explicit physical feature identifiers only, compares outline displacement, flags differing revisions and source decision/installation statements, and supplies both source references. These are review candidates, including legitimate historical changes; it does not resolve chronology or supersede accepted geometry. Existing geometric design/exclusion collision checks still run across disciplines.

Supported automatic geographic controls are currently explicit WGS84 longitude/latitude in the Kitsap region. State-plane coordinate tables, bearing/distance traverses, monument-relative offsets, CAD imports, GeoPDF transforms, point/line features, multiple-detail segmentation and source-image overlay editing still require further implementation. Generic feature labels are deliberately not automatic identity matches. No real sponsor plan or live model extraction was used for calibration quality benchmarking in this change; automated checks use synthetic drawings and mocked model responses. Existing documents require explicit reprocessing to generate the new proposals; accepted evidence is preserved.

## Test-parcel audit and discovery correction — November 7, 2026

Audit of live imported documents found no `site_geometry` facts. The as-built drawing page's vision pass rejected all 12 observations; historical diagnostics retained counts, not individual rejection reasons, so the precise causes cannot be reconstructed. Accepting prose facts cannot supply a location. A cited image transcription that does not match OCR is now retained as proposed visual evidence when an image hash and page region exist; it never becomes an exact text quote. Missing provenance remains rejected.

The county search link supplied an unformatted tax ID, which returned zero results. The formatted ID returned the parcel and public attachments. The new bounded adapter reads parcel-search/detail HTML, deduplicates attachment IDs, retains permit/submission context and lists selected-import PDF candidates without fetching files. Live validation found 115 public attachments for the test parcel. They were added to its candidate list unselected. Survey, wetland, revised civil and approved septic site-plan attachments are present. The public portal does not establish that all later reports are published; discovery remains partial. Different attachment IDs with matching filenames are retained until content/revision comparison.

The renderer/calibrator now accepts open LineStrings and Points as well as polygons. Drafts use dashed strokes and pale fills. Non-area features never subtract an exclusion area. Document-level geometry counts explain when parsing produced no geometry. This does not implement automatic matching of ordinary survey bearings or raster sheet registration.

The next required alignment work is a common project survey coordinate frame with explicit per-sheet transforms, matching control points and residuals, uncertainty labels, retained originals, and independent discipline/revision/status selectors. Registration must support reference-map controls, state-plane coordinates and monument-relative dimensions, not require printed WGS84 coordinates. Do not independently stretch each discipline to fit the parcel, snap away disagreements, or infer that a visually plausible placement is accepted. ## Shared reference and per-sheet alignment — November 8 follow-up

The alignment workspace now registers original PDF pages to shared named controls. Enter coordinates from the imported survey's stated datum (EPSG:2285 Washington North US survey feet or EPSG:4326 longitude/latitude), source page/revision and stated accuracy. Approximate GIS references are explicitly labeled screening. Unsupported datums require conversion outside this release; bearing/distance traverses and monument-relative dimensions are not yet interpreted automatically.

For each sheet, match at least three noncollinear fitting controls and one separate check point by clicking the cached original page or entering page-width coordinates. Extra reference controls may be omitted from individual sheets. Zoom supports precise selection. A least-squares similarity transform allows translation, rotation and uniform scale; no independent axis stretch or rubber-sheet warping hides disagreement. Fit RMS, each point's residual and the maximum independent-check residual remain visible separately from absolute reference accuracy. These are observed control errors, not confidence intervals or guarantees between/outside control points. User tolerance is a coordination threshold, not an engineering standard.

Each registration is pinned to the document hash, page and reference fingerprint. Changes invalidate affected registrations; prior project snapshots retain their source versions. The API recomputes transforms, uses revision concurrency checks and records the editor. Accepting placement does not accept the source features or confer agency approval. Only separately accepted features on reviewed survey alignments with known reference accuracy can become accepted exclusions; screening, unknown-accuracy and proposed alignments remain proposed geometry. Invalid source features retain review issues instead of breaking the viewer.

The viewer overlays original pages even without extracted geometry, so incomplete discipline plans can be inspected. Discipline, revision and individual-sheet visibility plus image opacity allow comparison. Dashed sheet borders indicate unreviewed alignment. Conflicts remain listed across hidden layers. Vector features use the same per-page transform. Raster pixels alone do not produce collision checks: those still require extracted or reviewed vector geometry. Unrelated details/insets on a page need separate segmentation in a future release; register only sheets with a single consistent plan frame.

Page previews use bounded Poppler rendering, project authorization and a content-hash cache at 1600 pixels. No new hosted viewer integration or model calls are required. Higher-resolution/vector source viewing, automatic control identification, richer uncertainty surfaces, CAD/GeoPDF import and authoritative survey control selection for the test parcel remain future work. This release provides assisted registration rather than claiming automatic alignment of the test parcel's plans.

Deployment requires `20261108061544_sheet_alignment.sql` before saving new project alignment revisions. The migration adds the alignment field to the existing revision RPC allowlist and preserves its membership and concurrency checks.

## Display before review (implemented November 8, 2026)

Rendering and computational eligibility are now separate. Extracted outlines are grouped by immutable source document/page and drawn over the original page using page-width units, bottom-left origin, y-up coordinates and the actual image aspect ratio. A source-page selector, discipline toggles and feature inspector replace hundreds of individually collapsed previews. Original pages load on demand through the existing authenticated endpoint.

`provisional-parcel-shape-v1` fits explicitly labeled full parcel outlines to assessor GIS with an orientation-preserving similarity transform. It checks perimeter agreement, shape overlap, competing orientations, written dimension scale, explicit different parcel identifiers, multiple frames and feature containment. Eligible same-page features share that transform. Existing manual registration takes precedence, including invalidated manual references. Proposed placement retains source hash, anchor observation and fit diagnostics. It is never survey control, reviewer acceptance or an input to envelope subtraction. Approximate GIS fits do not generate foot-level cross-document location conflicts; source revision/status conflicts remain visible.

The live test corpus renders 328 outlines across 133 pages, with 22 provisional geographic features across 15 pages. These include barn and access outlines as well as parcel boundaries. Counts include active older extraction retained on incomplete newer pages. One of 329 active geometry observations has no usable sheet outline. The remaining 306 sheet outlines have no geographic placement; this release does not claim majority automatic georeferencing. Sheet-only location gaps are summarized by shared page/frame instead of hundreds of separate missing-geometry warnings. Fact review decisions and their queue are unchanged.

The next automation work is source-frame detection and registration transfer between drawings using independently matched common controls, with crop/rotation/scale and revision provenance. Floors, sections, insets and vicinity maps must retain separate frames. A written dimension alone supplies scale, not geographic origin or orientation. Review should resolve a disputed frame or cross-document identity and propagate that decision to its observations, rather than require per-outline coordinate entry. Further model-driven frame extraction needs a measured quality/cost evaluation; it is not implemented by this deterministic display release.
